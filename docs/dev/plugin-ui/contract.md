# Plugin UI preview contract v1

Status: implementation contract for the Sveltos pilot. Common envelope and graphs are reusable by any cub plugin; no plugin is required to offer a preview it cannot compute.

A JSON document has `apiVersion: "confighub.com/plugin-preview/v1"`, `kind: "PluginPreview"`, `producer: {name, version}`, `exportedAt` (RFC3339 export time, NOT observation time), `scope: {description}`, `capabilities: ["preview"]`, `inventory: {nodes: [], edges: []}`, `proposal: {nodes: [], edges: []}`, and `issues: [{severity: "warning"|"error", code, message}]`.

Each node has required string `id`, `kind`, `name`; optional string `namespace`; optional `details` object with string values. Optional `hub` contains proposed `spaceSlug`, `unitSlug`, `targetSlug`, `targetsSpace` strings, never fabricated UUIDs. IDs are unique per graph. Edges have string `from`, `to`, `relation`, reference nodes within their own graph and are unique triples. Details and identifiers are text, never HTML. Graphs are sorted by node ID and edge triple. Unknown keys are ignored for additive compatibility; unknown API versions and invalid mandatory fields are rejected. Empty arrays are arrays, not null.

Inventory describes only supported objects supplied as inputs, never claims exhaustive live discovery. A `selects` edge records a selector or explicit reference match; it does not claim actual delivery. A `records-match` edge preserves a match from supplied status when the planner uses that fallback; it is not a fresh observation. Proposal describes future ConfigHub structure. Missing health has no default value. Filtered/skipped inputs and planning problems are explicit issues. Do not include raw Secret/config bodies, arbitrary annotations or credentials. `exportedAt` may vary; everything else is deterministic for the same inputs/options. Error exit may carry a valid JSON document; stdout contains only JSON, diagnostics use stderr.

Sveltos inventory nodes: ClusterProfile, SveltosCluster or Cluster, HelmChart, ConfigMap references. IDs include kind/namespace/name and parent profile for charts. Keep unselected clusters and filtered profiles in inventory, clearly reflecting the supplied scope. Details include selector, chart version and planning disposition. Proposal nodes: Space, Target, Unit. Edges: variantOf (child -> base), targets (space -> target), contains (space -> unit), registers (targets space -> target). Variant Units and management delivery/health Units are included when planned. Space details may include stage, sourceProfile, clusterIdentity. Hub lookup hints must match generated onboarding slugs.

Capabilities describe offered operations, not authorization. v1 offers preview only. Connected actions remain authenticated server operations. A local artifact is never automatically uploaded or executed.
