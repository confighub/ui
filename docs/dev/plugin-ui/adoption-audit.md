# Bounded cub plugin machine-output and UI-contract adoption audit

Date: 2026-09-30. Read-only inventory; no plugin actions that alter a cluster or ConfigHub account were run. `--help`, installed-plugin listing, and local source inspection only.

## Scope and limits

This is a bounded audit, not an inventory of every plugin in the world. The inspected universe is: (1) the 15 plugin install slots returned by local `cub plugin list -o json`; (2) their install metadata; (3) local `/Users/alexis/code` trees, including manifests, Go `plugin.HandleHook` declarations, and documented manual plugin package shapes; and (4) the 28 repositories visible to `gh repo list confighub --limit 300` on 2026-09-30, using names/descriptions and selective read-only source-tree inspection for plugin-described candidates. There is no authoritative finite public plugin catalog in the inspected `cub` install/list implementation: arbitrary GitHub repos, URLs, binaries, directories and archives are accepted. The report counts **14 installed families, 7 additional local source plugin families, and 1 GitHub-advertised private plugin repository** (=22 named families across this bounded evidence set). It does not claim that these are all possible or all worldwide cub plugins. A repo-list entry with an unclear purpose is tracked as unresolved below, not included in the count.

Deduplication: `install` and `installer` are two slots for the `installer` command family; `scan` and command `check`/alias `scan` are one family; `workshop` contributes four distinct commands from one plugin; `argo` and `flux` both come from the `/Users/alexis/code/examples` checkout but remain separate plugins. This yields 14 plugin families across 15 slots.

## Shared contract being evaluated

Reference: `/Users/alexis/code/ui/docs/dev/plugin-ui/contract.md` (PluginPreview v1), `/Users/alexis/code/ui/docs/dev/plugin-ui/README.md`, and `/Users/alexis/code/ui/docs/dev/plugin-ui/lessons.md`.

Cross-plugin practices apply to every family, including plugins with no UI: retain human-readable defaults; offer explicit machine output; keep machine stdout pure and put diagnostics on stderr; document valid partial-result/nonzero-exit behavior; make producer/version, input scope, provenance, export time, and unknown state explicit; never translate missing data into healthy/unmanaged/empty-fleet claims; allowlist safe fields and exclude credentials, Secret bodies, and arbitrary metadata; verify deterministic output, partial errors, unsupported inputs, and compatibility; keep UI capabilities separate from authorization/installation. Preview itself is optional. Where offered, v1 requires `apiVersion: confighub.com/plugin-preview/v1`, `kind: PluginPreview`, producer/version, export time, declared scope/capabilities, inventory and proposal graphs, issues, deterministic sorted IDs/edges, explicit partial/skipped-input issues, and no credentials/raw Secret/config bodies. A preview is a local artifact and grants no authorization. See `README.md` lines 50–64 and `contract.md` lines 3–13.

The Flux lesson is directly applicable: use the plugin's real planner/match semantics; do not invent live inventory or health from static inputs; preserve partial planning errors in valid JSON where that behavior is supported; distinguish local proposal from connected actions; test the adapter against source output; and describe adoption as a per-plugin checklist, not a blanket claim (`lessons.md` lines 8–40, 85–86).

## Audit conclusion

Adopt the cross-plugin author checklist across the **14 installed families** and apply it to the **7 additional local plugin sources** and **1 GitHub-advertised private plugin repo** found in this bounded pass. Treat a plugin as Preview v1-compatible only after checking the actual installed/released implementation and a representative machine-output fixture. Strongest evidence for plan-to-preview adapters is Argo, Flux, Sveltos source, cub-gen local proposal outputs, and potentially Kubara/Workshop after schema and redaction work. Flux already has an adapter proof; Sveltos source implements the envelope, while the currently installed `v0.10.0` help did not expose its JSON flag. The example managers and AICR need specific commands/output contracts inspected before assigning adapter work. UI preview remains optional. Do not infer schema stability from a `--json` flag, Go JSON tags, or the ConfigHub plugin manifest's version.
